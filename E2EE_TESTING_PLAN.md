# План запуска и тестирования E2EE

## 1. Деплой бэкенда на VPS

Бэкенд нужно пересобрать и задеплоить, чтобы миграция `V6__e2ee_keys.sql` применилась и новые API-эндпоинты заработали.

```bash
# На VPS в папке с бэкендом:
docker compose down
docker compose build --no-cache backend
docker compose up -d
```

После старта проверь логи:
```bash
docker compose logs -f backend | grep -i "e2ee\|V6\|Started"
```

Должно быть видно:
- `Successfully applied 1 migration to schema "public", now at version 6` (Flyway)
- `Started MessengerApplication` — сервер запустился

> **СТАТУС: ВЫПОЛНЕНО** — бэкенд задеплоен, миграция V6 применена, сервер работает.

## 3. Что тестировать — чек-лист

### A. Регистрация ключей (автоматическая)

**Что происходит:** При входе в аккаунт приложение автоматически генерирует ключи и загружает их на сервер.

**Как проверить:**
- Войди в аккаунт на **устройстве 1** (например, `test` / `test1234`)
- В логах бэкенда должно появиться сообщение о регистрации ключей
- Также можно вызвать API напрямую:

```bash
curl -H "Authorization: Bearer <token>" http://31.130.150.246:3000/api/v1/keys/count
```

Должно вернуть `{"count": 100}` (или близко к тому).

| Статус | Результат |
|--------|-----------|
| [ ]    |           |

---

### B. Шифрование сообщений в личном чате

**Как проверить:**
1. Войди на **устройстве 1** (пользователь A)
2. Войди на **устройстве 2** (пользователь B) — ключи тоже зарегистрируются автоматически
3. Открой личный чат между A и B
4. В заголовке чата должна быть **иконка замка** (зелёная) рядом с именем
5. Отправь текстовое сообщение от A к B
6. B должен получить сообщение и прочитать его нормально
7. В базе данных при этом поле `text` будет содержать **шифротекст** (base64), а `encrypted = true`

**Что может пойти не так:**
- Если ключи одного из пользователей не загрузились — сообщение отправится без шифрования (fallback)
- Если расшифровка не удалась — вместо текста покажет "Не удалось расшифровать"

| Статус | Результат |
|--------|-----------|
| [t]    | Работет корректно  |

---

### C. Зашифрованные медиа и голосовые

**Как проверить:**
1. В личном чате отправь **фото** от A к B
2. B должен увидеть фото нормально
3. Отправь **голосовое сообщение** — B должен его прослушать
4. На сервере файлы хранятся в зашифрованном виде

| Статус | Результат |
|--------|-----------|
| [ ]    |           |

---

### D. Push-уведомления

**Как проверить:**
1. Отправь сообщение пользователю B, когда приложение у него **свёрнуто**
2. Push-уведомление должно показать: **имя отправителя** в заголовке и **"Новое сообщение"** в теле (без содержания)

| Статус | Результат |
|--------|-----------|
| [ ]    |           |

---

### E. Информация о шифровании

**Как проверить:**
1. Открой личный чат
2. Нажми **три точки** (меню) → **"Шифрование"**
3. Откроется шторка с информацией о сквозном шифровании и **кодом безопасности**
4. Код безопасности можно сравнить на двух устройствах — они должны совпадать

| Статус | Результат |
|--------|-----------|
| [ ]    |           |

---

### F. Превью в списке чатов

**Как проверить:**
1. Отправь зашифрованное сообщение
2. В списке чатов на главном экране последнее сообщение должно показать текст нормально (если сессия активна) или "Зашифрованное сообщение"

| Статус | Результат |
|--------|-----------|
| [ ]    |           |

---

### G. Обратная совместимость

**Как проверить:**
1. Старые сообщения (до E2EE) должны отображаться как обычно
2. Групповые чаты пока работают **без шифрования** (E2EE для групп — это Подэтап B)

| Статус | Результат |
|--------|-----------|
| [ ]    |           |

## 6. Полезные команды для отладки

### Проверить количество pre-keys пользователя:
```bash
curl -H "Authorization: Bearer <token>" http://31.130.150.246:3000/api/v1/keys/count
```

### Посмотреть логи бэкенда:
```bash
ssh root@31.130.150.246
cd /opt/messenger-backend
docker compose logs -f backend
```

### Проверить содержимое сообщения в БД:
```bash
docker compose exec postgres psql -U messenger -d messenger -c \
  "SELECT id, text, encrypted, encrypted_file_key FROM messages ORDER BY created_at DESC LIMIT 5;"
```

### Проверить таблицы E2EE ключей:
```bash
docker compose exec postgres psql -U messenger -d messenger -c \
  "SELECT user_id, registration_id, created_at FROM e2ee_identity_keys;"
```
