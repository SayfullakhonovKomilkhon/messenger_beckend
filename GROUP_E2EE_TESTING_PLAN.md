# План тестирования E2EE для групповых чатов (Sender Keys Protocol)

## 1. Деплой бэкенда на VPS

Бэкенд нужно пересобрать, чтобы миграция `V7__group_sender_keys.sql` применилась и новые API-эндпоинты для Sender Keys заработали.

```bash
# На VPS:
cd /opt/messenger-backend
git fetch origin main
git reset --hard origin/main
docker compose build --no-cache backend
docker compose down backend
docker compose up -d backend
```

После старта проверь логи:
```bash
docker compose logs backend --tail 30 | grep -i "flyway\|V7\|sender\|Started"
```

Должно быть видно:
- `Successfully applied 1 migration to schema "public", now at version 7` (Flyway)
- `Started MessengerApplication` — сервер запустился

## 3. Что тестировать — чек-лист

### A. Инициализация ключей при открытии группы

**Что происходит:** При открытии группового чата приложение автоматически создаёт SenderKey для текущего пользователя и распределяет его всем участникам через 1:1 Signal-сессии.

**Как проверить:**
1. Войди как **пользователь A** (test / test1234)
2. Войди как **пользователь B** (test123 / 123456)
3. Создай групповой чат (или открой существующий) с A и B
4. Открой группу на **обоих устройствах**
5. В логах Flutter должно появиться:
   - `[E2EE-Group] Initialized sender key session for group <groupId>`
   - `[E2EE-Group] Distributed sender keys to N members`
   - `[E2EE-Group] Processed sender key from <userId>`

**Как проверить в БД:**
```bash
docker compose exec postgres psql -U messenger -d messenger -c \
  "SELECT group_id, sender_id, recipient_id, consumed, created_at FROM group_sender_keys ORDER BY created_at DESC LIMIT 10;"
```

| Статус | Результат |
|--------|-----------|
| [ ]    |           |

### C. Шифрование текстовых сообщений в группе

**Как проверить:**
1. Отправь текстовое сообщение от **A** в групповой чат
2. **B** должен получить сообщение и прочитать его нормально
3. Отправь сообщение от **B** к **A** — тоже должно прочитаться

**Проверка в БД — текст должен быть зашифрован:**
```bash
docker compose exec postgres psql -U messenger -d messenger -c \
  "SELECT id, LEFT(text, 50) as text_preview, encrypted, sender_id FROM messages WHERE conversation_id = '<GROUP_ID>' ORDER BY created_at DESC LIMIT 5;"
```

- Поле `text` должно содержать **base64-шифротекст** (не читаемый текст)
- Поле `encrypted` должно быть `true`

**Что может пойти не так:**
- Если SenderKey не распределён — сообщение отправится **без шифрования** (fallback)
- Если расшифровка не удалась — покажет "Не удалось расшифровать"

### I. Ротация ключей при удалении участника

**Как проверить:**
1. Создай группу с **3 участниками** (A, B, C)
2. Все трое открывают группу (ключи распределяются)
3. **Удали участника C** из группы (через админку или API)
4. В логах Flutter у A и B должно появиться:
   - `[E2EE-Group] Rotated sender keys for group <groupId>`
5. Сообщения после удаления C продолжают шифроваться/расшифровываться между A и B
6. C больше не может расшифровать новые сообщения

**Проверка через БД — старые ключи C удалены:**
```bash
docker compose exec postgres psql -U messenger -d messenger -c \
  "SELECT sender_id, recipient_id FROM group_sender_keys WHERE group_id = '<GROUP_ID>';"
```
— C не должен присутствовать ни как sender, ни как recipient

| Статус | Результат |
|--------|-----------|
| [ ]    |           |

### J. Добавление нового участника

**Как проверить:**
1. Группа с A и B, оба открыли чат
2. Добавь участника **C** в группу
3. В логах Flutter у A и B:
   - `[E2EE-Group] Distributed sender keys to N members`
4. C открывает группу — в логах:
   - `[E2EE-Group] Processed sender key from A`
   - `[E2EE-Group] Processed sender key from B`
5. Все трое могут обмениваться зашифрованными сообщениями

## 6. Полезные команды для отладки

### Проверить таблицу group_sender_keys:
```bash
docker compose exec postgres psql -U messenger -d messenger -c \
  "SELECT group_id, sender_id, recipient_id, consumed, created_at FROM group_sender_keys ORDER BY created_at DESC LIMIT 10;"
```

### Проверить зашифрованные сообщения в группе:
```bash
docker compose exec postgres psql -U messenger -d messenger -c \
  "SELECT id, LEFT(text, 50), encrypted, sender_id FROM messages WHERE conversation_id = '<GROUP_ID>' ORDER BY created_at DESC LIMIT 5;"
```

### Посмотреть логи бэкенда:
```bash
docker compose logs -f backend | grep -i "sender\|group\|e2ee\|distribute"
```

### Очистить sender keys для группы (для повторного тестирования):
```bash
docker compose exec postgres psql -U messenger -d messenger -c \
  "DELETE FROM group_sender_keys WHERE group_id = '<GROUP_ID>';"
```

### Проверить API sender keys (pending):
```bash
curl -H "Authorization: Bearer <token>" http://31.130.150.246:3000/api/v1/groups/sender-keys/pending
```
